# Design

## Existing catalog contract

The existing generic `rest_json` ingestor already has a THG catalog fixture in
`internal/workspace_knowledge/ingestion/rest_json/example_thg_hub.go`.

Catalog endpoint:

```text
https://hub.thgfulfill.com/api/public/catalog
```

Pagination is page/limit based. The expected product fields are:

| Upstream field | Canonical meaning |
|---|---|
| `id` | stable source ID; THG uses CUID values such as `cmqv14yk...` |
| `thgSku` | human-facing THG SKU |
| `sku` | vendor/internal SKU |
| `name` | product name |
| `category` | product category |
| `origin` | fulfillment origin |
| `sizes`, `colors` | variant dimensions |
| `priceFrom`, `priceTo`, `currency` | price range and currency |
| `images` | ordered image URLs; not used by this module |
| `status` | `Active`/`Inactive` availability |
| `updatedAt` | source update timestamp |

The canonical PDP URL is:

```text
https://thgfulfill.com/vi/catalog?productId={id}
```

The URL template was updated in commit `c33d393`.

## Data flow

```text
THG REST catalog
  -> rest_json ingestor
  -> KnowledgeOS product asset / PayloadV1.SourceURL
  -> runtime.CandidatesForLead
  -> models.KnowledgeCandidate.SourceURL
  -> facebook.PickSuggestedProduct
  -> facebook.LeadSuggestion
  -> control.LeadNotice
  -> Telegram render.Lead
```

For a crawl-created lead, the two runtime paths are:

### Server API / connector path

`internal/server/router.go` creates an optional lead-suggestion callback when
`cfg.LeadSuggestionEnabled` is true. The callback builds a knowledge runtime
builder and calls `facebook.BuildLeadSuggestion`. The callback is passed through
the connector routes to `crawl_ingest.go`, where it is invoked when a
`leadingest.LeadEvent` is emitted.

### Worker path

`cmd/worker/main.go` reads `LEAD_SUGGESTION_ENABLED`. When enabled, it creates
one KnowledgeOS builder and a comment-path `MessageGenerator`, then invokes
`facebook.BuildLeadSuggestion` from the worker's lead notifier callback.

## Grounding behavior

`PickSuggestedProduct` iterates the already-ranked candidates and returns the
first candidate satisfying both conditions:

- `Kind == "POD_product"`;
- `SourceURL` is non-empty after trimming.

The returned name and URL are copied from the candidate. No URL is generated by
the model. If no candidate qualifies, the suggestion contains no product.

`BuildLeadSuggestion` is best-effort and returns an empty suggestion when:

- the KnowledgeOS builder is unavailable;
- the comment generator is unavailable;
- the organization profile is unavailable;
- retrieval fails; or
- generation fails.

On generation failure, the grounded product name/link may still be returned so
the operator can open the product manually.

## Telegram rendering contract

`control.LeadNotice` now carries:

- `SuggestedReply`;
- `ProductName`;
- `ProductURL`.

`render.Lead` renders optional blocks only when values are non-empty. The base
lead notification remains unchanged when the feature is disabled or no product
was retrieved.

The renderer is plain text, not MarkdownV2. This avoids escaping problems in
SKU, CUID, product names, and query-string URLs.

## Configuration

```env
LEAD_SUGGESTION_ENABLED=false
```

Set it to `true` only after the catalog source has been configured and synced.
The suggestion generator uses the comment-path LLM configuration:

```env
LLM_COMMENT_BASE_URL=https://api.deepseek.com
LLM_COMMENT_API_KEY=<provider-secret>
OPENAI_COMMENT_MODEL=deepseek-v4-flash
```

The current provider-neutral code supports the configured OpenAI-compatible
provider. Do not put secrets in Git. Production secrets belong in
`/etc/thg-scraper/env`.

## Operational prerequisite: catalog sync

The code does not silently create a KnowledgeOS source. An operator must ensure
the organization has a source pointing to the THG catalog, using the existing
`rest_json` adapter and the field map in `ExampleConfigTHGHub`. The source must
be synced successfully before enabling suggestions.

Verify that product assets contain:

- product title/name;
- `POD_product` asset type;
- `PayloadV1.SourceURL` equal to
  `https://thgfulfill.com/vi/catalog?productId=<id>`;
- optional SKU, price and image fields.

If the catalog endpoint is blocked from the VPS, fix network/allow-listing or
use the approved catalog access path before enabling the flag. Do not bypass
Cloudflare or scrape around authentication/risk controls.

## Failure and rollback

Disable without reverting code:

```env
LEAD_SUGGESTION_ENABLED=false
```

Then restart only the affected services:

```bash
sudo systemctl restart thg-scraper thg-worker
```

No full VPS reboot is required.
